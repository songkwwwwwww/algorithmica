모듈러 산술(그리고 일반적인 계산 대수학)에서는 [모듈러 나눗셈](../modular/#modular-division), [소수성 테스트](../modular/#fermats-theorem), 또는 조합론적 값 계산을 위해 숫자를 $n$제곱해야 하는 경우가 많습니다. 이때 보통 $\Theta(n)$보다 적은 연산으로 이를 계산하고자 합니다.

*이진 거듭제곱(binary exponentiation)* 또는 *거듭제곱법(exponentiation by squaring)*은 다음과 같은 관찰에 기반하여 $O(\log n)$번의 곱셈으로 $n$제곱을 계산할 수 있게 해주는 방법입니다:

$$
\begin{aligned}
    a^{2k}       &= (a^k)^2
\\  a^{2k + 1}   &= (a^k)^2 \cdot a
\end{aligned}
$$

$a^n$을 계산하기 위해 재귀적으로 $a^{\lfloor n / 2 \rfloor}$을 계산하고 이를 제곱한 다음, $n$이 홀수이면 $a$를 추가로 곱합니다. 이는 다음 점화식에 해당합니다:

$$
a^n = f(a, n) = \begin{cases}
   1,               && n = 0
\\ f(a, \frac{n}{2})^2,     && 2 \mid n
\\ f(a, n - 1) \cdot a, && 2 \nmid n
\end{cases}
$$

재귀 호출이 두 번 일어날 때마다 $n$이 최소 절반으로 줄어들기 때문에, 이 점화식의 깊이와 총 곱셈 횟수는 최대 $O(\log n)$이 됩니다.

### 재귀적 구현

점화식이 있으므로 알고리즘을 케이스 매칭 재귀 함수로 구현하는 것이 자연스럽습니다:

```c++
const int M = 1e9 + 7; // 모듈러스
typedef unsigned long long u64;

u64 binpow(u64 a, u64 n) {
    if (n == 0)
        return 1;
    if (n % 2 == 1)
        return binpow(a, n - 1) * a % M;
    else {
        u64 b = binpow(a, n / 2);
        return b * b % M;
    }
}
```

벤치마크에서는 $n = m - 2$를 사용하여 모듈로 $m$에 대한 $a$의 [곱셈 역원](../modular/#modular-division)을 계산합니다:

```c++
u64 inverse(u64 a) {
    return binpow(a, M - 2);
}
```

여기서는 알고리즘 문제 해결(competitive programming)에서 조합론 문제의 체크섬을 계산할 때 흔히 사용되는 $m = 10^9+7$을 사용합니다. 이 값은 소수(이진 거듭제곱을 통해 역원을 구할 수 있음)이고, 충분히 크며, 덧셈 시 `int` 범위를 넘지 않고, 곱셈 시 `long long` 범위를 넘지 않으며, `1e9 + 7`로 입력하기 쉽기 때문입니다.

코드에서 컴파일 타임 상수로 사용하므로, 컴파일러는 모듈로 연산을 [곱셈으로 대체](/hpc/arithmetic/division/)하여 최적화할 수 있습니다(컴파일 타임 상수가 아니더라도 매직 상수를 직접 계산하여 빠른 리덕션에 사용하는 것이 여전히 저렴합니다).

실행 경로와 그에 따른 실행 시간은 $n$의 값에 따라 달라집니다. 이 특정 $n$의 경우, 기본 구현은 호출당 약 330ns가 소요됩니다. 재귀는 어느 정도 [오버헤드](/hpc/architecture/functions/)를 발생시키므로, 이를 반복문 절차로 풀어내는 것이 좋습니다.

### 반복적 구현

$a^n$의 결과는 $a$를 2의 거듭제곱들로 곱한 것으로 표현할 수 있으며, 이는 $n$의 이진 표현에서 1인 비트들에 대응합니다. 예를 들어 $n = 42 = 32 + 8 + 2$라면 다음과 같습니다:

$$
a^{42} = a^{32+8+2} = a^{32} \cdot a^8 \cdot a^2 
$$

이 곱을 계산하기 위해 $n$의 비트를 순회하며 두 개의 변수를 유지할 수 있습니다. 하나는 $a^{2^k}$의 값이고, 다른 하나는 $n$의 하위 $k$개 비트를 고려한 현재까지의 곱입니다. 각 단계에서 $n$의 $k$번째 비트가 설정되어 있으면 현재 곱에 $a^{2^k}$를 곱하고, 어떤 경우든 $a^k$를 제곱하여 다음 반복에서 사용할 $a^{2^k \cdot 2} = a^{2^{k+1}}$을 얻습니다.

```c++
u64 binpow(u64 a, u64 n) {
    u64 r = 1;
    
    while (n) {
        if (n & 1)
            r = r * a % M;
        a = a * a % M;
        n >>= 1;
    }
    
    return r;
}
```

반복적 구현은 호출당 약 180ns가 소요됩니다. 핵심 계산은 동일하지만, 성능 향상은 주로 단축된 의존성 체인(dependency chain)에서 옵니다. `a = a * a % M`은 루프가 진행되기 전에 완료되어야 하지만, 이제 `r = r * a % M`과 동시에 실행될 수 있습니다.

또한 $n$이 상수인 경우 [모든 분기를 예측 가능하게 만들어](/hpc/pipelining/branching/) 스케줄러가 실행할 내용을 미리 알 수 있게 해줌으로써 성능 이득을 얻습니다. 하지만 컴파일러는 이를 활용하지 못하고 `while(n) n >>= 1` 루프를 풀지(unroll) 못합니다. 이를 30번의 고정된 반복을 수행하는 `for` 루프로 다시 작성할 수 있습니다:

```c++
u64 inverse(u64 a) {
    u64 r = 1;
    
    #pragma GCC unroll(30)
    for (int l = 0; l < 30; l++) {
        if ( (M - 2) >> l & 1 )
            r = r * a % M;
        a = a * a % M;
    }

    return r;
}
```

이렇게 하면 컴파일러가 필요한 명령어만 생성하도록 강제하여 10ns를 더 절약하고 총 실행 시간을 ~170ns로 단축할 수 있습니다.

성능은 $n$의 이진 길이뿐만 아니라 이진수 1의 개수에도 영향을 받는다는 점에 유의하십시오. $n$이 $2^{30}$인 경우 추가 곱셈을 수행할 필요가 없으므로 약 20ns 정도 더 적게 걸립니다.
