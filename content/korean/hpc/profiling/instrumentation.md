*계측 (Instrumentation)*은 프로그램에 타이머나 기타 추적 코드를 삽입하는 것을 의미하는 다소 복잡한 용어입니다. 가장 간단한 예는 유닉스 계열 시스템에서 `time` 유틸리티를 사용하여 프로그램 전체의 실행 시간을 측정하는 것입니다.

더 일반적으로는 프로그램의 *어느 부분*에 최적화가 필요한지 알고 싶을 때가 많습니다. 컴파일러나 IDE와 함께 제공되는 도구 중에는 지정된 함수의 시간을 자동으로 측정하는 도구도 있지만, 언어에서 제공하는 시간 관련 메서드를 사용하여 직접 측정하는 것이 더 견고한 방법입니다.

```cpp
clock_t start = clock();
do_something();
float seconds = float(clock() - start) / CLOCKS_PER_SEC;
printf("do_something() took %.4f", seconds);
```

여기서 한 가지 미묘한 점은, `clock` 함수가 마이크로초($10^{-6}$) 단위의 현재 타임스탬프를 반환하고 자체적으로 완료되는 데도 수백 나노초가 걸리기 때문에 매우 빠른 함수의 실행 시간은 이 방식으로 측정할 수 없다는 것입니다. 다른 모든 시간 관련 유틸리티도 마찬가지로 최소 마이크로초 단위의 정밀도를 가지는데, 이는 저수준 최적화의 세계에서는 영겁의 시간과도 같습니다.

더 높은 정밀도를 얻으려면 루프에서 함수를 반복적으로 호출하고, 전체 시간을 한 번 측정한 다음, 이를 반복 횟수로 나눌 수 있습니다.

```cpp
#include <stdio.h>
#include <time.h>

const int N = 1e6;

int main() {
    clock_t start = clock();

    for (int i = 0; i < N; i++)
        clock(); // clock 함수 자체를 벤치마킹함

    float duration = float(clock() - start) / CLOCKS_PER_SEC;
    printf("%.2fns per iteration\n", 1e9 * duration / N);

    return 0;
}
```

또한 데이터가 캐싱되거나, 컴파일러에 의해 최적화되어 사라지거나, 기타 유사한 부수 효과의 영향을 받지 않도록 주의해야 합니다. 이는 별도의 매우 복잡한 주제이며, [이 장의 마지막](../benchmarking)에서 더 자세히 다룰 예정입니다.

### 이벤트 샘플링 (Event Sampling)

계측은 특정 알고리즘의 성능에 대한 유용한 통찰을 줄 수 있는 다른 유형의 정보를 수집하는 데도 사용될 수 있습니다. 예를 들면 다음과 같습니다.

- 해시 함수의 경우, 입력의 평균 길이에 관심이 있습니다.
- 이진 트리의 경우, 트리의 크기와 높이가 중요합니다.
- 정렬 알고리즘의 경우, 수행되는 비교 횟수를 알고 싶습니다.

이와 유사한 방식으로, 이러한 알고리즘 특화 통계를 계산하는 카운터를 코드에 삽입할 수 있습니다.

카운터를 추가하면 오버헤드가 발생한다는 단점이 있지만, 무작위로 아주 적은 비율의 호출에 대해서만 카운팅을 수행함으로써 오버헤드를 거의 완벽하게 완화할 수 있습니다.

```c++
void query() {
    if (rand() % 100 == 0) {
        // 통계 업데이트
    }
    // 주요 로직
}
```

샘플링 비율이 충분히 작다면, 호출당 남는 유일한 오버헤드는 난수 생성과 조건 확인뿐입니다. 흥미롭게도 통계학적인 기교를 사용하여 이를 조금 더 최적화할 수 있습니다.

수학적으로 우리가 여기서 하는 일은 성공할 때까지 [베르누이 분포 (Bernoulli distribution)](https://ko.wikipedia.org/wiki/베르누이_분포) (성공 확률 $p$가 샘플링 비율과 같음)에서 반복적으로 샘플링하는 것입니다. 첫 번째 성공이 나올 때까지 필요한 베르누이 샘플링의 횟수를 알려주는 또 다른 분포가 있는데, 이를 [기하 분포 (Geometric distribution)](https://ko.wikipedia.org/wiki/기하_분포)라고 합니다. 우리는 대신 이 분포에서 샘플링하고 그 값을 감소하는 카운터로 사용할 수 있습니다.

```c++
void query() {
    static next_sample = geometric_distribution(sample_rate);
    if (next_sample--) {
        next_sample = geometric_distribution(sample_rate);
        // ...
    }
    // ...
}
```

이 방식을 사용하면 매 호출마다 새로운 난수를 샘플링할 필요가 없으며, 통계를 계산하기로 결정했을 때만 카운터를 재설정하면 됩니다.

이와 같은 기술들은 대규모 프로젝트의 라이브러리 알고리즘 개발자들이 최종 프로그램의 성능에 큰 영향을 주지 않으면서 프로파일링 데이터를 수집하기 위해 자주 사용합니다.
