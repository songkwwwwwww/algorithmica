현대 컴퓨터 메모리는 매우 계층적입니다. 속도와 크기가 서로 다른 여러 *캐시 계층*으로 구성되며, 일반적으로 상위 계층은 지연 시간을 줄이기 위해 하위 계층에서 가장 자주 액세스하는 데이터를 저장합니다. 각 상위 계층은 일반적으로 하위 계층보다 훨씬 빠르지만 크기는 작고 비용은 더 비쌉니다.

![](../img/hierarchy.png)

추상적으로 다양한 메모리 장치는 특정 저장 용량 $M$을 가지며, 고정된 시간 내에 $B$ 크기의 블록 단위(바이트 단위가 아님!)로 데이터를 읽거나 쓸 수 있는 모듈로 설명할 수 있습니다.

이러한 관점에서 각 메모리 유형은 몇 가지 중요한 특징을 가집니다.

- *전체 크기* $M$;
- *블록 크기* $B$; 
- *지연 시간(latency)*, 즉 1바이트를 가져오는 데 걸리는 시간;
- *대역폭(bandwidth)*, 블록 크기에 지연 시간을 곱한 것보다 높을 수 있으며, 이는 I/O 작업이 "중첩"될 수 있음을 의미합니다.
- *비용*, 칩 가격, 에너지 요구 사항, 유지 관리 등을 포함한 감가상각된 비용입니다.

다음은 2021년 기준 일반 하드웨어의 대략적인 비교표입니다.

| 유형 | $M$      | $B$ | 지연 시간 | 대역폭 | $/GB/월[^pricing] |
|:-----|:---------|-----|---------|-----------|:------------------|
| L1   | 10K      | 64B | 2ns     | 80G/s     | -                 |
| L2   | 100K     | 64B | 5ns     | 40G/s     | -                 |
| L3   | 코어당 1M | 64B | 20ns    | 20G/s     | -                 |
| RAM  | GB 단위   | 64B | 100ns   | 10G/s     | 1.5               |
| SSD  | TB 단위   | 4K  | 0.1ms   | 5G/s      | 0.17              |
| HDD  | TB 단위   | -   | 10ms    | 1G/s      | 0.04              |
| S3   | $\infty$ | -   | 150ms   | $\infty$  | 0.02[^S3]         |

실제로는 각 메모리 유형마다 구체적인 특징이 있으며, 이제 하나씩 살펴보겠습니다.

[^pricing]: 가격 정보는 [Google Cloud Platform](https://cloud.google.com/products/calculator?skip_cache=true)에서 가져왔습니다.
[^S3]: 클라우드 스토리지는 일반적으로 [여러 티어](https://aws.amazon.com/s3/storage-classes/)를 제공하며, 데이터 액세스 빈도가 낮을수록 점진적으로 저렴해집니다.

### 휘발성 메모리 (Volatile Memory)

RAM까지의 모든 계층은 정전이나 기타 재난 발생 시 데이터를 보존하지 않기 때문에 *휘발성 메모리*라고 부릅니다. 속도가 빠르기 때문에 컴퓨터가 켜져 있는 동안 임시 데이터를 저장하는 데 사용됩니다.

가장 빠른 것부터 순서대로 나열하면 다음과 같습니다.

- **CPU 레지스터**: CPU가 모든 중간 값을 저장하는 데 사용하는 지연 시간이 없는 데이터 셀로, 일종의 메모리 유형으로 생각할 수 있습니다. 개수가 한정되어 있으며(예: "범용" 레지스터 16개), 성능상의 이유로 모든 레지스터를 사용해야 하는 경우도 있습니다.
- **CPU 캐시**: 최신 CPU에는 여러 계층의 캐시(L1, L2, 종종 L3, 드물게 L4까지)가 있습니다. 가장 낮은 계층은 코어 간에 공유되며 일반적으로 코어 수에 따라 확장됩니다(예: 10코어 CPU는 약 10M의 L3 캐시를 가짐).
- **RAM (Random Access Memory)**: 첫 번째로 확장 가능한 메모리 유형입니다. 요즘은 퍼블릭 클라우드에서 0.5테라바이트 RAM이 장착된 머신을 임대할 수 있습니다. 대부분의 작업 데이터가 저장되는 곳입니다.

CPU 캐시 시스템에는 *캐시 라인(cache line)*이라는 중요한 개념이 있습니다. 이는 CPU와 RAM 간의 데이터 전송 기본 단위입니다. 대부분의 아키텍처에서 캐시 라인의 크기는 64바이트입니다. 즉, 모든 메인 메모리는 64바이트 블록으로 나뉘며, 단 1바이트를 요청(읽기 또는 쓰기)하더라도 해당 캐시 라인에 속한 63개의 인접 데이터를 원하든 원치 않든 함께 가져오게 됩니다.

CPU 레벨의 캐싱은 캐시 라인의 마지막 액세스 시간을 기준으로 자동으로 발생합니다. 액세스 시 캐시 라인의 내용은 가장 낮은 캐시 계층에 배치된 다음, 제때 다시 액세스되지 않으면 점차 상위 계층으로 쫓겨납니다(evicted). 프로그래머가 이 과정을 명시적으로 제어할 수는 없지만, 어떻게 작동하는지 자세히 연구할 가치가 있으며 이는 [다음 장](/hpc/cpu-cache)에서 다룰 것입니다.

### 비휘발성 메모리 (Non-Volatile Memory)

CPU 캐시와 RAM의 데이터 셀이 소량의 전자(주기적으로 누출되어 보충이 필요함)를 부드럽게 저장하는 반면, *비휘발성 메모리* 유형의 데이터 셀은 수백 개의 전자를 저장합니다. 이를 통해 전원 없이도 장기간 데이터를 유지할 수 있지만, 전자가 많을수록 실리콘 원자와 충돌할 가능성이 커져 성능과 내구성이 저하됩니다.

영구적으로 데이터를 저장하는 방법은 많지만, 프로그래머 관점에서는 다음과 같은 방법이 주요합니다.

- **SSD (Solid State Drives)**: 지연 시간이 0.1ms($10^5$ ns) 정도로 상대적으로 낮지만 비용이 높고, 각 셀에 쓸 수 있는 횟수가 제한되어 있어 수명이 한정적입니다. 크기가 작고 움직이는 부품이 없어 모바일 기기와 대부분의 노트북에서 사용됩니다.
- **HDD (Hard Disk Drives)**: 읽기/쓰기 헤드가 달린 [회전하는 물리적 디스크](https://www.youtube.com/watch?v=3owqvmMf6No&feature=emb_title)라는 점이 독특합니다. 특정 메모리 위치를 읽으려면 디스크가 올바른 위치로 회전할 때까지 기다린 다음 헤드를 정확히 그 위치로 옮겨야 합니다. 이로 인해 1바이트를 무작위로 읽는 시간이 다음 1MB의 데이터를 읽는 시간과 비슷해지는(보통 수 밀리초 단위) 매우 특이한 액세스 패턴이 발생합니다. 냉각 시스템을 제외하고 컴퓨터에서 기계적으로 움직이는 부품이 있는 유일한 부분이기 때문에 하드 디스크는 꽤 자주 고장 납니다(데이터 센터용 HDD의 평균 수명은 약 3년).
- **NAS (Network-Attached Storage)**: 네트워크로 연결된 다른 장치를 사용하여 데이터를 저장하는 방식입니다. 두 가지 뚜렷한 유형이 있습니다. 첫 번째는 다른 컴퓨터의 파일 시스템을 네트워크를 통해 마운트하는 프로토콜인 네트워크 파일 시스템(NFS)입니다. 다른 하나는 [Amazon S3](https://aws.amazon.com/s3/)와 같이 퍼블릭 클라우드의 저장소 최적화 머신들에 의해 뒷받침되는 API 기반 분산 저장 시스템입니다. 내부적으로는 저렴한 HDD나 더 [이색적인](https://aws.amazon.com/storagegateway/vtl/) 저장 장치를 사용합니다. NFS는 동일한 데이터 센터에 있는 경우 HDD보다 빠르게 작동할 수도 있지만, 퍼블릭 클라우드의 객체 저장소는 보통 50-100ms의 지연 시간을 가집니다. 일반적으로 가용성을 높이기 위해 고도로 분산되고 복제됩니다.

SSD/HDD는 RAM보다 눈에 띄게 느리기 때문에 이 레벨 이하의 모든 장치를 보통 *외부 메모리(external memory)*라고 부릅니다.

CPU 캐시와 달리 외부 메모리는 명시적으로 제어할 수 있습니다. 이는 여러 경우에 유용하지만, 대부분의 프로그래머는 이를 추상화하여 메인 메모리의 확장으로 사용하고 싶어 하며, 운영 체제는 [가상 메모리](../virtual)를 통해 이를 지원합니다.
