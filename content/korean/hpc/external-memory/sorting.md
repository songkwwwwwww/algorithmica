이제 새로운 [외부 메모리 모델](../model)에 실제로 유용한 알고리즘을 설계해 보겠습니다. 이 섹션의 목표는 더 복잡한 것들을 서서히 쌓아 올려 최종적으로 *외부 정렬(external sorting)*과 그 흥미로운 응용 분야에 도달하는 것입니다.

알고리즘은 표준 병합 정렬(merge sort) 알고리즘을 기반으로 하므로, 먼저 주요 프리미티브를 도출해야 합니다.

### 병합 (Merge)

**문제.** 길이가 $N$과 $M$인 두 개의 정렬된 배열 $a$와 $b$가 주어졌을 때, 모든 요소를 포함하는 길이가 $N + M$인 단일 정렬 배열 $c$를 생성하십시오.

정렬된 배열을 병합하는 표준 투 포인터(two-pointer) 기술은 다음과 같습니다.

```cpp
void merge(int *a, int *b, int *c, int n, int m) {
    int i = 0, j = 0;
    for (int k = 0; k < n + m; k++) {
        if (i < n && (j == m || a[i] < b[j]))
            c[k] = a[i++];
        else
            c[k] = b[j++];
    }
}
```

메모리 작업 측면에서 우리는 단순히 $a$와 $b$의 모든 요소를 선형적으로 읽고 $c$의 모든 요소를 선형적으로 씁니다. 이러한 읽기와 쓰기는 버퍼링될 수 있으므로 $SCAN(N+M)$ I/O 작업으로 작동합니다.

지금까지의 예시는 간단했으며, 최종 답을 블록 크기 $B$로 나누는 것을 제외하고는 RAM 모델과 분석 결과가 크게 다르지 않았습니다. 하지만 그렇지 않은 경우도 있습니다.

**$k$-웨이 병합 ($k$-way merging).** 두 개가 아닌 $k$개의 배열(총 크기 $N$)을 병합해야 하는 알고리즘의 변형을 고려해 보겠습니다. 마찬가지로 $k$개의 값을 살펴보고 그중 최솟값을 선택하여 $c$에 쓰고, 해당 반복자(iterator) 중 하나를 증가시킵니다.

표준 RAM 모델에서 점근적 복잡도는 $k$배가 될 것입니다. 각 다음 요소를 채우기 위해 $O(k)$번의 비교를 수행해야 하기 때문입니다. 하지만 외부 메모리 모델에서는 메모리 내에서 수행하는 모든 작업의 비용이 0이므로, 메모리에 $(k+1)$개의 전체 블록을 담을 수 있는 한(즉, $k = O(\frac{M}{B})$인 경우) 점근적 복잡도는 변하지 않습니다.

계산 모델을 소개할 때 언급했던 [$M \gg B$ 가정](../model)을 기억하시나요? $\epsilon > 0$에 대해 $M \geq B^{1+ε}$인 경우, 메모리에 다항식 미만(sub-polynomial) 개수의 블록을 담을 수 있으며, 여기에는 확실히 $O(\frac{M}{B})$가 포함됩니다. 이 조건을 *높은 캐시 가정(tall cache assumption)*이라고 하며, 많은 다른 외부 메모리 알고리즘에서 필수적으로 요구됩니다.

### 병합 정렬 (Merge Sorting)

표준 병합 정렬 알고리즘의 "일반적인" 복잡도는 $O(N \log_2 N)$입니다. $O(\log_2 N)$개의 각 "계층"에서 알고리즘은 총 $N$개의 모든 요소를 거치며 선형 시간에 병합해야 합니다.

외부 메모리 모델에서 크기 $M$의 블록을 읽으면, 이미 메모리에 들어와 있으므로 해당 요소들을 "공짜로" 정렬할 수 있습니다. 이런 방식으로 배열을 연속된 요소들의 $O(\frac{N}{M})$개 블록으로 나누고 기본 단계로 각각 따로 정렬한 다음 병합할 수 있습니다.

![](../img/k-way.png)

이는 I/O 작업 측면에서 병합 정렬의 처음 $O(\log M)$ 계층은 비용이 0이며, 비용이 발생하는 계층은 $O(\log_2 \frac{N}{M})$개뿐임을 의미합니다. 각 계층은 총 $O(\frac{N}{B})$ IOPS로 병합 가능합니다. 이로 인해 총 I/O 복잡도는 다음과 같습니다.

$$
O\left(\frac{N}{B} \log_2 \frac{N}{M}\right)
$$

이것은 꽤 빠릅니다. 1GB의 메모리와 10GB의 데이터가 있다면, 데이터를 단순히 읽는 것보다 약 3배 조금 넘는 노력으로 정렬할 수 있다는 뜻입니다. 흥미롭게도 더 잘할 수 있습니다.

### $k$-웨이 병합 정렬 ($k$-way Mergesort)

조금 전에 외부 메모리 모델에서 $k$개의 배열을 병합하는 것이 두 개의 배열을 병합하는 것만큼 쉽다는 것을 배웠습니다(배열을 읽는 비용만 발생). 이 사실을 여기에 적용해 보는 것은 어떨까요?

이전처럼 크기 $M$의 각 블록을 메모리 내에서 정렬하되, 각 병합 단계에서는 정렬된 블록을 쌍으로 나누지 않고 $k$-웨이 병합 중에 메모리에 담을 수 있는 만큼의 많은 블록을 가져옵니다. 이렇게 하면 병합 트리의 높이가 크게 줄어들면서도 각 계층은 여전히 $O(\frac{N}{B})$ IOPS로 처리됩니다.

한 번에 몇 개의 정렬된 배열을 병합할 수 있을까요? 각 배열당 하나의 블록을 위한 메모리가 필요하므로 정확히 $k = \frac{M}{B}$개입니다. 총 계층 수가 $\log_{\frac{M}{B}} \frac{N}{M}$으로 줄어들기 때문에 총 복잡도는 다음과 같이 줄어듭니다.

$$
SORT(N) \stackrel{\text{def}}{=} O\left(\frac{N}{B} \log_{\frac{M}{B}} \frac{N}{M} \right)
$$

예를 들어 10GB의 데이터, 1GB의 메모리가 있고 HDD의 블록 크기가 약 1MB라고 가정해 보겠습니다. 그러면 $\frac{M}{B} = 1000$이고 $\frac{N}{M} = 10$이 되어 로그 값이 1보다 작아집니다(즉, $\log_{1000} 10 = \frac{1}{3}$). 물론 배열을 읽는 것보다 빠르게 정렬할 수는 없으므로, 이 분석은 데이터셋이 매우 크고 메모리가 작거나 블록 크기가 큰 경우에 적용됩니다. 요즘 실생활에서는 이런 일이 드뭅니다.

### 실제 구현

더 현실적인 제약 조건 하에서 $\log_{\frac{M}{B}} \frac{N}{M}$ 계층을 사용하는 대신 단 두 계층만 사용할 수 있습니다. 하나는 데이터를 $M$개 요소의 블록으로 정렬하는 것이고, 다른 하나는 그 블록들을 한 번에 모두 병합하는 것입니다. 이렇게 하면 I/O 작업 관점에서 데이터셋을 단 두 번만 훑으면 됩니다. 1GB의 RAM과 1MB의 블록 크기를 사용하면 이 방식으로 최대 테라바이트 크기의 배열을 정렬할 수 있습니다.

C++에서 첫 번째 단계가 어떻게 보이는지 확인해 보겠습니다. 이 프로그램은 정렬되지 않은 정수가 포함된 수 기가바이트의 바이너리 파일을 열고, 256MB 블록 단위로 읽어 메모리에서 정렬한 다음 `part-000.bin`, `part-001.bin`, `part-002.bin` 등의 이름으로 파일에 다시 씁니다.

```cpp
const int B = (1<<20) / 4; // 1 MB 정수 블록
const int M = (1<<28) / 4; // 가용 메모리

FILE *input = fopen("input.bin", "rb");
std::vector<FILE*> parts;

while (true) {
    static int part[M]; // 사용 후 바로 삭제하는 것이 좋음
    int n = fread(part, 4, M, input);

    if (n == 0)
        break;
    
    // 블록을 메모리 내에서 정렬
    std::sort(part, part + n);
    
    char fpart[sizeof "part-999.bin"];
    sprintf(fpart, "part-%03d.bin", parts.size());

    printf("%d 요소를 %s에 쓰는 중...\n", n, fpart);

    FILE *file = fopen(fpart, "wb");
    fwrite(part, 4, n, file);
    fclose(file);
    
    file = fopen(fpart, "rb");
    parts.push_back(file);
}

fclose(input);
```

이제 남은 일은 이들을 하나로 병합하는 것입니다. 현대 HDD의 대역폭은 매우 높을 수 있고 병합할 파트가 많을 수 있으므로, 이 단계의 I/O 효율성만이 유일한 관심사는 아닙니다. $O(k)$ 비교로 최솟값을 찾는 것보다 더 빠르게 $k$개 배열을 병합할 방법이 필요합니다. 힙 정렬(heapsort)과 거의 동일한 방식으로 이 $k$개 요소에 대해 최소 힙(min-heap)을 유지하면 요소당 $O(\log k)$ 시간에 처리할 수 있습니다.

구현 방법은 다음과 같습니다. 먼저 힙(`C++의 priority_queue`)이 필요합니다.

```c++
struct Pointer {
    int key, part; // 요소 자체와 해당 파트의 번호

    bool operator<(const Pointer& other) const {
        return key > other.key; // std::priority_queue는 기본적으로 최대 힙임
    }
};

std::priority_queue<Pointer> q;
```

그런 다음 버퍼를 할당하고 채웁니다.

```c++
const int nparts = parts.size();

auto buffers = new int[nparts][B]; // 각 파트용 버퍼
int *l = new int[nparts],          // 이미 처리된 버퍼 요소의 수
    *r = new int[nparts];          // 버퍼 크기 (완전히 차지 않은 경우 대비)

// 이제 각 파트의 버퍼를 채우고 해당 요소들을 힙에 추가합니다.
for (int part = 0; part < nparts; part++) {
    l[part] = 1; // 요소가 힙에 있으면 "처리됨"으로 간주합니다.
    r[part] = fread(buffers[part], 4, B, parts[part]);
    q.push({buffers[part][0], part});
}
```

이제 힙이 비워질 때까지 요소를 꺼내 결과 파일에 넣기만 하면 됩니다. 이때 요소를 묶음(batch) 단위로 신중하게 읽고 씁니다.

```cpp
FILE *output = fopen("output.bin", "w");

int outbuffer[B]; // 출력 버퍼
int buffered = 0; // 버퍼 내 요소 수

while (!q.empty()) {
    auto [key, part] = q.top();
    q.pop();

    // 최솟값을 출력 버퍼에 씀
    outbuffer[buffered++] = key;
    // 파일에 커밋해야 하는지 확인
    if (buffered == B) {
        fwrite(outbuffer, 4, B, output);
        buffered = 0;
    }

    // 필요한 경우 해당 파트의 새 블록을 가져옴
    if (l[part] == r[part]) {
        r[part] = fread(buffers[part], 4, B, parts[part]);
        l[part] = 0;
    }

    // 해당 파트의 요소를 모두 처리하지 않았다면 새 요소를 읽음
    if (l[part] < r[part]) {
        q.push({buffers[part][l[part]], part});
        l[part]++;
    }
}

// 출력 버퍼에 남은 내용 쓰기
fwrite(outbuffer, 4, buffered, output);

// 정리
delete[] buffers;
for (FILE *file : parts)
    fclose(file);
fclose(output);
```

이 구현은 특별히 효율적이거나 안전해 보이지는 않지만(기본적으로 순수 C 스타일이므로), 저수준 메모리 API를 사용하는 방법을 보여주는 좋은 교육적 예시입니다.

### 조인 (Joining)

정렬은 그 자체로도 쓰이지만 주로 다른 작업을 위한 중간 단계로 사용됩니다. 외부 정렬의 중요한 실제 사례 중 하나는 데이터베이스 및 기타 데이터 처리 애플리케이션에서 사용되는 조인(SQL의 "join")입니다.

**문제.** 두 개의 튜플 리스트 $(x_i, a_{x_i})$와 $(y_i, b_{y_i})$가 주어졌을 때, $x_k = y_k$를 만족하는 리스트 $(k, a_{x_k}, b_{y_k})$를 출력하십시오.

최적의 솔루션은 두 리스트를 정렬한 다음 표준 투 포인터 기술을 사용하여 병합하는 것입니다. 여기서 I/O 복잡도는 정렬과 동일하며, 배열이 이미 정렬되어 있다면 $O(\frac{N}{B})$에 불과합니다. 이것이 대부분의 데이터 처리 애플리케이션(데이터베이스, MapReduce 시스템)이 테이블을 최소한 부분적으로라도 정렬된 상태로 유지하려는 이유입니다.

**다른 접근 방식.** 이 분석은 외부 메모리 환경, 즉 전체 데이터셋을 읽을 메모리가 없는 경우에만 적용 가능하다는 점에 유의하세요. 현실 세계에서는 다른 방법이 더 빠를 수도 있습니다.

그중 가장 간단한 것은 아마도 다음과 같은 *해시 조인(hash join)*일 것입니다.

```python
def join(a, b):
    d = dict(a)
    for x, y in b:
        if x in d:
            yield d[x]
```

외부 메모리에서 해시 테이블로 두 리스트를 조인하는 것은 실행 불가능합니다. 각 블록에서 단 하나의 요소만 사용되더라도 $O(M)$번의 블록 읽기가 발생하기 때문입니다.

또 다른 방법은 기수 정렬(radix sort)과 같은 대체 정렬 알고리즘을 사용하는 것입니다. 특히 기수 정렬은 모든 가능한 키에 대해 버퍼를 유지할 충분한 메모리가 있는 경우 $O(\frac{N}{B} \cdot w)$ 블록 읽기로 작동하며, 키가 작고 데이터셋이 큰 경우 더 빠를 수 있습니다.
