title: SIMD 병렬성

---

정수 배열의 합을 계산하는 다음의 작은 프로그램을 살펴보겠습니다.

```c++
const int n = 1e5;
int a[n], s = 0;

int main() {
    for (int t = 0; t < 100000; t++)
        for (int i = 0; i < n; i++)
            s += a[i];

    return 0;
}
```

이 코드를 일반적인 `g++ -O3` 옵션으로 컴파일하여 실행하면 2.43초가 걸립니다.

이제 코드의 맨 처음에 다음과 같은 마법 같은 지시어를 추가해 보겠습니다.

```c++
#pragma GCC target("avx2")
// ...나머지는 이전과 동일합니다
```

동일한 환경에서 컴파일하고 실행하면 1.24초 만에 끝납니다. 코드 한 줄이나 최적화 레벨을 바꾸지 않았는데도 거의 두 배나 빨라졌습니다.

여기서 일어난 일은 코드가 실행될 컴퓨터에 대한 정보를 조금 제공한 것입니다. 구체적으로, 대상 CPU가 "AVX2"라고 불리는 x86 명령어 세트 확장 기능을 지원한다는 것을 컴파일러에게 알려주었습니다. AVX2는 x86을 위한 여러 "SIMD 확장" 중 하나입니다. 이러한 확장 기능에는 "단일 명령, 다중 데이터"(single instruction, multiple data, SIMD) 방식을 사용하여 128, 256 또는 512비트의 데이터를 담을 수 있는 특수 레지스터에서 작동하는 명령어들이 포함되어 있습니다. SIMD 명령어는 단일 스칼라 값으로 작업하는 대신 레지스터의 데이터를 8, 16, 32 또는 64비트 블록으로 나누고 이들에 대해 동일한 연산을 병렬로 수행하여 성능을 비례적으로 향상시킵니다[^power].

[^power]: 일부 CPU에서 특히 무거운 SIMD 명령어는 더 많은 에너지를 소비하므로 전체 전력 소비의 균형을 맞추기 위해 [클럭 다운(downclocking)](https://blog.cloudflare.com/on-the-dangers-of-intels-frequency-scaling/)이 필요할 수 있으며, 따라서 실시간 속도 향상이 항상 비례적인 것은 아닙니다.

![](img/simd.png)

이러한 확장 기능은 비교적 최신 기능이며, 하위 호환성을 유지하면서 CPU에서 점진적으로 구현되었습니다[^avx512]. 더 전문화된 명령어를 추가하는 것 외에도, 가장 중요한 차이점은 점진적으로 더 넓은 레지스터를 도입했다는 것입니다.

특히 AVX2는 256비트 레지스터 작업을 위한 명령어를 가지고 있는 반면, 기본적으로 GCC는 128비트 SSE2 이후의 기능은 활성화되지 않았다고 가정합니다. 따라서 최적화 도구에 한 번에 4개가 아닌 8개의 정수를 더하는 명령어를 사용할 수 있다고 알려준 후 성능이 두 배로 향상된 것입니다.

[^avx512]: AVX512부터는 하위 호환성이 더 이상 유지되지 않습니다. 데이터 압축, 암호화 또는 머신러닝과 같은 특정 요구 사항에 맞춘 다양한 "버전(flavor)"이 존재합니다.

![](img/intel-extensions.webp)

위의 사례처럼 컴파일러는 종종 SIMD 명령어를 사용하여 간단한 루프를 다시 작성하는 일을 훌륭하게 수행합니다. 이 최적화를 [자동 벡터화(auto-vectorization)](auto-vectorization)라고 하며, SIMD를 사용하는 가장 대중적인 방법입니다.

문제는 이것이 특정 유형의 루프에서만 작동하며, 작동하더라도 최적의 결과를 내지 못하는 경우가 많다는 점입니다. 자동 벡터화의 한계를 이해하려면 직접 팔을 걷어붙이고 더 낮은 수준에서 이 기술을 탐구해 보아야 합니다. 이것이 바로 이번 장에서 우리가 할 일입니다.
