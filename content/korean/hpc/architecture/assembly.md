CPU는 *기계어(machine language)*로 제어됩니다. 기계어는 다음과 같은 사항을 지정하는 이진 인코딩된 명령어의 스트림입니다.

- 명령어 번호 (*옵코드(opcode)*라고 함)
- *피연산자(operand)*가 무엇인지 (있는 경우)
- 그리고 *결과*를 어디에 저장할지 (생성되는 경우)

기계어를 훨씬 더 인간 친화적으로 표현한 것을 *어셈블리어(assembly language)*라고 하며, 기계어 명령어를 참조하기 위해 니모닉 코드를 사용하고 레지스터 및 기타 저장 위치를 참조하기 위해 상징적인 이름을 사용합니다.

바로 본론으로 들어가서, Arm 어셈블리에서 두 숫자를 더하는 방법(`*c = *a + *b`)은 다음과 같습니다.

```nasm
; *a = x0, *b = x1, *c = x2
ldr w0, [x0]    ; x0가 가리키는 곳에서 4바이트를 w0로 로드
ldr w1, [x1]    ; x1이 가리키는 곳에서 4바이트를 w1로 로드
add w0, w0, w1  ; w0와 w1을 더하고 결과를 w0에 저장
str w0, [x2]    ; w0의 내용을 x2가 가리키는 곳에 쓰기
```

x86 어셈블리에서의 동일한 작업은 다음과 같습니다.

```nasm
; *a = rsi, *b = rdi, *c = rdx 
mov eax, DWORD PTR [rsi]  ; rsi가 가리키는 곳에서 4바이트를 eax로 로드
add eax, DWORD PTR [rdi]  ; rdi에 저장된 값을 eax에 더함
mov DWORD PTR [rdx], eax  ; eax의 내용을 rdx가 가리키는 곳에 쓰기
```

어셈블리는 고수준 프로그래밍 언어에 비해 구문 구조가 많지 않다는 점에서 매우 단순합니다. 위의 예제에서 관찰할 수 있는 점은 다음과 같습니다.

- 프로그램은 명령어의 시퀀스이며, 각 명령어는 이름 다음에 가변적인 개수의 피연산자가 오는 형태로 작성됩니다.
- `[reg]` 구문은 레지스터에 저장된 포인터를 "역참조(dereferencing)"하는 데 사용되며, x86에서는 크기 정보(여기서 `DWORD`는 32비트를 의미함)를 접두사로 붙여야 합니다.
- `;` 기호는 다른 언어의 `#`이나 `//`와 유사하게 한 줄 주석에 사용됩니다.

어셈블리는 그래야만 하기 때문에 매우 미니멀한 언어입니다. 기계어와 어셈블리 사이에 거의 1:1 대응이 이루어질 정도로 기계어를 최대한 가깝게 반영합니다. 실제로 *역어셈블(disassembly)*[^disassembly]이라는 과정을 통해 컴파일된 프로그램을 다시 어셈블리 형태로 바꿀 수 있습니다. 다만 주석과 같이 필수적이지 않은 정보는 보존되지 않습니다.

[^disassembly]: Linux에서 컴파일된 프로그램을 역어셈블하려면 `objdump -d {이진-파일-경로}`를 호출하면 됩니다.

위의 두 코드 조각은 단지 구문적으로만 다른 것이 아닙니다. 둘 다 컴파일러가 생성한 최적화된 코드이지만, Arm 버전은 4개의 명령어를 사용하는 반면 x86 버전은 3개를 사용합니다. `add eax, [rdi]` 명령어는 로드와 더하기를 한 번에 수행하는 소위 *융합된 명령어(fused instruction)*입니다. 이는 [CISC](../isa#risc-vs-cisc) 방식이 제공할 수 있는 장점 중 하나입니다.

아키텍처 간에는 이 외에도 훨씬 더 많은 차이점이 있으므로, 앞으로 이 책의 나머지 부분에서는 대부분의 독자가 최적화의 대상으로 삼을 x86에 대한 예제만 제공할 것입니다. 물론 소개되는 많은 개념은 아키텍처에 구애받지 않습니다.

### 명령어와 레지스터

역사적인 이유로 대부분의 어셈블리어에서 명령어 니모닉은 매우 짧습니다. 사람들이 어셈블리를 직접 손으로 작성하고 동일한 공통 명령어 세트를 반복해서 작성하던 시절에는, 타이핑할 글자 하나를 줄이는 것이 정신 건강을 지키는 길 중 하나였습니다.

예를 들어, `mov`는 "워드 저장/로드(store/load a word)", `inc`는 "1 증가(increment by 1)", `mul`은 "곱하기(multiply)", `idiv`는 "정수 나눗셈(integer division)"을 의미합니다. [x86 참조 문서](https://www.felixcloutier.com/x86/)에서 이름으로 명령어 설명을 찾아볼 수 있지만, 대부분의 명령어는 이름에서 짐작할 수 있는 기능을 수행합니다.

대부분의 명령어는 결과를 첫 번째 피연산자에 기록하며, 이 피연산자는 이전에 본 `add eax, [rdi]` 예제처럼 계산에도 참여할 수 있습니다. 피연산자는 레지스터, 상수 값 또는 메모리 위치가 될 수 있습니다.

**레지스터**는 `rax`, `rbx`, `rcx`, `rdx`, `rdi`, `rsi`, `rbp`, `rsp`, 그리고 `r8`-`r15`까지 총 16개가 있습니다. 문자로 된 이름들은 역사적인 이유로 붙여졌습니다. `rax`는 "누산기(accumulator)", `rcx`는 "카운터(counter)", `rdx`는 "데이터(data)" 등입니다. 하지만 물론 꼭 그 용도로만 사용해야 하는 것은 아닙니다.

또한 비슷한 이름을 가진 32비트, 16비트, 8비트 레지스터도 있습니다 (`rax` → `eax` → `ax` → `al`). 이들은 완전히 분리된 것이 아니라 *별칭(aliased)* 관계입니다. `rax`의 하위 32비트는 `eax`, `eax`의 하위 16비트는 `ax`인 식입니다. 이는 호환성을 유지하면서 다이 면적을 절약하기 위해 만들어졌으며, 컴파일된 프로그래밍 언어에서 기본 타입 캐스팅이 보통 비용이 들지 않는 이유이기도 합니다.

이들은 [일부 예외](../functions)를 제외하고 대부분의 명령어에서 원하는 대로 사용할 수 있는 *범용(general-purpose)* 레지스터들입니다. 또한 [부동 소수점 산술](/hpc/arithmetic/float)을 위한 별도의 레지스터 세트, [벡터 확장](/hpc/simd)에서 사용되는 매우 넓은 레지스터들, 그리고 [제어 흐름](../loops)에 필요한 몇 가지 특수 레지스터들이 있지만, 이에 대해서는 차차 알아보겠습니다.

**상수**는 정수 또는 부동 소수점 값입니다: `42`, `0x2a`, `3.14`, `6.02e23`. 이들은 기계어 코드 안에 직접 포함되기 때문에 흔히 *즉시값(immediate values)*이라고 불립니다. 명령어 인코딩의 복잡성을 크게 증가시킬 수 있기 때문에, 일부 명령어는 즉시값을 지원하지 않거나 고정된 일부 값만 허용합니다. 어떤 경우에는 상수 값을 레지스터에 로드한 다음 즉시값 대신 사용해야 합니다.

숫자 값 외에도 `hello` 또는 `world\n`과 같은 문자열 상수와 그들만의 작은 연산 세트가 있지만, 이는 우리가 여기서 다루지 않을 어셈블리어의 다소 모호한 부분입니다.

### 데이터 이동

일부 명령어는 동일한 니모닉을 가질 수 있지만 피연산자 유형이 다를 수 있습니다. 이 경우 수행하는 작업이 약간 다를 수 있고 실행 시간이 다를 수 있으므로 별개의 명령어로 간주됩니다. `mov` 명령어가 그 생생한 예인데, 메모리와 레지스터 사이 또는 두 레지스터 사이의 데이터 이동과 관련된 약 20가지의 서로 다른 형태가 있습니다. 이름에도 불구하고 값을 레지스터로 *이동(move)*하는 것이 아니라 *복사(copy)*하여 원본을 보존합니다.

두 레지스터 간에 데이터를 복사할 때, `mov` 명령어는 내부적으로 *레지스터 리네이밍(register renaming)*을 수행합니다. 즉, 레지스터 X가 참조하는 값이 실제로는 레지스터 Y에 저장되어 있음을 CPU에 알립니다. 이는 명령어를 읽고 디코딩하는 것 외에 추가적인 지연을 발생시키지 않습니다. 같은 이유로 두 레지스터를 바꾸는 `xchg` 명령어도 비용이 들지 않습니다.

위에서 융합된 `add`를 본 것처럼, 모든 메모리 작업에 `mov`를 사용할 필요는 없습니다. 일부 산술 명령어는 피연산자로 메모리 위치를 편리하게 지원합니다.

### 주소 지정 모드

메모리 주소 지정은 `[]` 연산자로 수행되지만, 레지스터에 저장된 값을 단지 메모리 위치로 재해석하는 것 이상의 일을 할 수 있습니다. 주소 피연산자는 구문에서 최대 4개의 매개변수를 받습니다.

```
SIZE PTR [base + index * scale + displacement]
```

여기서 `displacement`는 정수 상수여야 하며 `scale`은 2, 4, 또는 8 중 하나여야 합니다. 이 연산이 하는 일은 포인터 `base + index * scale + displacement`를 계산하고 이를 역참조하는 것입니다.

복잡한 주소 지정을 사용하는 것은 포인터를 직접 역참조하는 것보다 [최대 1 사이클 더 느릴 뿐](/hpc/cpu-cache/pointers)이며, 예를 들어 구조체 배열이 있고 $i$번째 요소의 특정 필드를 로드하고 싶을 때 유용할 수 있습니다.

주소 지정 연산자 앞에는 데이터가 몇 비트 필요한지에 대한 크기 지정자를 붙여야 합니다.

- `BYTE`: 8비트
- `WORD`: 16비트
- `DWORD`: 32비트
- `QWORD`: 64비트

또한 [80비트](/hpc/arithmetic/float)를 위한 드문 `TBYTE`와 [128, 256, 512비트](/hpc/simd)를 위한 `XMMWORD`, `YMMWORD`, `ZMMWORD`가 각각 있습니다. 이 모든 타입은 대문자로 쓸 필요는 없지만, 대부분의 컴파일러가 대문자로 출력합니다.

주소 계산 그 자체로도 유용한 경우가 많습니다. `lea`("load effective address", 유효 주소 로드) 명령어는 피연산자의 메모리 주소를 계산하여 실제 메모리 작업을 수행하지 않고 한 사이클 만에 레지스터에 저장합니다. 원래 용도는 실제 메모리 주소를 계산하는 것이지만, 1번의 곱셈과 2번의 덧셈이 필요한 산술 트릭으로도 자주 사용됩니다. 예를 들어, 이 명령어로 3, 5, 9를 곱할 수 있습니다.

또한 결과를 다른 곳으로 옮겨야 할 때 별도의 `mov` 명령어가 필요하지 않기 때문에 `add`의 대체제로 자주 쓰입니다. `add`는 `a += b` 형태의 두 레지스터 모드에서만 작동하지만, `lea`를 사용하면 `a = b + c`(또는 그 중 하나가 상수라면 `a = b + c + d`)를 수행할 수 있습니다.

### 대안 구문

실제로 어셈블리로부터 기계어를 생성하는 프로그램인 *어셈블러(assembler)*는 여러 개가 있고 어셈블리어도 서로 다르지만, 현재는 두 개의 x86 구문만 널리 사용됩니다. 이들은 보통 그 시대의 프로그래밍에 지배적인 영향을 미쳤고 그 구문을 사용했던 두 회사의 이름을 따서 불립니다.

- 모든 Linux 도구에서 기본적으로 사용하는 *AT&T 구문*.
- Intel에서 기본적으로 사용하는 *Intel 구문*.

이러한 구문들은 각각 이를 사용하는 두 가지 주요 어셈블러의 이름을 따서 *GAS*(*GNU Assembler*) 및 *NASM*(*Netwide Assembler*)이라고도 불립니다.

우리는 이 장에서 Intel 구문을 사용했으며, 책의 나머지 부분에서도 가급적 이를 계속 사용할 것입니다. 비교를 위해 동일한 `*c = *a + *b` 예제가 AT&T 어셈블리에서는 어떻게 보이는지 확인해 보겠습니다.

```asm
movl (%rsi), %eax
addl (%rdi), %eax
movl %eax, (%rdx)
```

주요 차이점은 다음과 같이 요약할 수 있습니다.

1. *마지막* 피연산자가 대상을 지정하는 데 사용됩니다.
2. 레지스터와 상수 앞에는 각각 `%`와 `$`를 붙여야 합니다 (예: `addl $1, %rdx`는 `rdx`를 증가시킴).
3. 메모리 주소 지정은 `displacement(%base, %index, scale)` 형식을 갖습니다.
4. `;`와 `#` 모두 한 줄 주석에 사용할 수 있으며, `/* */`는 블록 주석에 사용할 수 있습니다.

그리고 가장 중요한 점은 AT&T 구문에서 명령어 이름 뒤에 접미사(`addq`, `movl`, `cmpq` 등)를 붙여 조작되는 피연산자의 크기를 지정해야 한다는 것입니다.

- `b` = 바이트 (8비트)
- `w` = 워드 (16비트)
- `l` = 롱 (32비트 정수 또는 64비트 부동 소수점)
- `q` = 쿼드 (64비트)
- `s` = 싱글 (32비트 부동 소수점)
- `t` = 10바이트 (80비트 부동 소수점)

Intel 구문에서는 이 정보가 피연산자로부터 추론됩니다 (이것이 포인터의 크기를 지정해야 하는 이유이기도 합니다).

x86 어셈블리를 생성하거나 소비하는 대부분의 도구는 두 구문 모두를 지원하므로, 원하는 구문을 선택해서 사용하면 되며 크게 걱정할 필요는 없습니다.
