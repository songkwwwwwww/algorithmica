부동 소수점 산술을 사용하는 사람들은 IQ 정규 분포 밈에 등장할 법합니다. 부동 소수점과 대부분의 사람들 사이의 관계는 보통 다음과 같이 진행되기 때문입니다.

- 초보 프로그래머는 부동 소수점을 마치 무한한 정밀도를 가진 마법의 데이터 타입인 것처럼 어디에나 사용합니다.
- 그러다 `0.1 + 0.2 != 0.3` 같은 현상이나 다른 기이한 점들을 발견하고는 당황하며, 모든 계산에 무작위 오차 항이 추가된다고 생각하기 시작합니다. 그래서 수년 동안 실수 데이터 타입을 완전히 피하게 됩니다.
- 마침내 마음을 다잡고 IEEE-754 부동 소수점 표준이 어떻게 작동하는지 읽어본 뒤, 이를 적절하게 사용하기 시작합니다.

불행히도 너무나 많은 사람이 여전히 2단계에 머물러 있으며, 부동 소수점 산술에 대해 수많은 오해를 키우고 있습니다. 부동 소수점이 근본적으로 부정확하고 불안정하며, 정수 산술보다 느리다고 생각하는 것이죠.

![](../img/iq.svg)

하지만 이것들은 모두 미신일 뿐입니다. 부동 소수점 산술은 특수 명령어 덕분에 정수 산술보다 *빠른* 경우가 많으며, 실수 표현은 철저하게 표준화되어 있고 반올림에 관한 단순하고 결정론적인 규칙을 따르므로 계산 오차를 안정적으로 관리할 수 있습니다.

실제로 부동 소수점은 매우 신뢰할 만해서, JavaScript와 같은 일부 고수준 프로그래밍 언어에는 정수 타입이 아예 없습니다. JavaScript에는 오직 하나의 `number` 타입만 존재하며, 내부적으로 64비트 `double`로 저장됩니다. 부동 소수점 산술의 작동 방식 덕분에 $-2^{53}$에서 $2^{53}$ 사이의 모든 정수와 이들을 포함한 계산 결과는 정확하게 저장될 수 있습니다. 따라서 프로그래머 관점에서는 별도의 정수 타입이 필요할 실질적인 이유가 거의 없습니다.

한 가지 주목할 만한 예외는 숫자에 비트 연산을 수행해야 할 때입니다. 부동 소수점 숫자에 대한 연산을 담당하는 보조 프로세서인 *부동 소수점 연산 장치(FPU)*는 대개 비트 연산을 지원하지 않습니다. 이 경우 숫자를 정수로 변환해야 하는데, 이는 JavaScript 기반 브라우저에서 매우 빈번하게 발생합니다. 이 때문에 Arm은 ["FJCVTZS"라는 특수 명령어](https://community.arm.com/developer/ip-products/processors/b/processors-ip-blog/posts/armv8-a-architecture-2016-additions)를 추가했습니다. 이는 "Floating-point Javascript Convert to Signed fixed-point, rounding toward Zero"의 약자로, 말 그대로 JavaScript와 똑같은 방식으로 실수를 정수로 변환합니다. 이는 소프트웨어와 하드웨어 간의 피드백 루프가 실제로 작동하는 흥미로운 사례입니다.

하지만 정수 산술을 흉내 내기 위해 실수 타입만을 사용하는 JavaScript 개발자가 아니라면, 부동 소수점 산술에 대한 더 심층적인 가이드가 필요할 것입니다. 이제 더 넓은 주제부터 시작해 보겠습니다.

## 실수 표현법 (Real Number Representations)

실수(정수가 아닌 수)를 다루어야 한다면 적용 가능성이 각기 다른 몇 가지 선택지가 있습니다. 이 글의 주요 주제인 부동 소수점 수로 넘어가기 전에, 사용 가능한 대안들과 그 배경을 논의해 보고자 합니다. 결국 부동 소수점 산술을 피하는 사람들에게도 나름의 이유가 있으니까요.

### 심볼릭 표현식 (Symbolic Expressions)

첫 번째이자 가장 번거로운 접근 방식은 결과값 자체가 아니라 그 값을 생성하는 대수적 표현식을 저장하는 것입니다.

간단한 예를 들어보겠습니다. 계산 기하학과 같은 일부 응용 분야에서는 숫자를 더하고 빼고 곱하는 것 외에도 반올림 없이 나누어야 하는 경우가 있습니다. 이때 두 정수의 비율로 정확하게 표현할 수 있는 유리수(rational number)를 생성할 수 있습니다.

```c++
struct r {
    int x, y;
};

r operator+(r a, r b) { return {a.x * b.y + a.y * b.x, a.y * b.y}; }
r operator*(r a, r b) { return {a.x * b.x, a.y * b.y}; }
r operator/(r a, r b) { return {a.x * b.x, a.y * b.y}; }
bool operator<(r a, r b) { return a.x * b.y < b.x * a.y; }
// ...이런 식으로 계속됩니다. 감이 오시죠?
```

이 비율을 기약분수로 만들면 이 표현을 유일하게 만들 수도 있습니다.

```c++
struct r {
    int x, y;
    r(int x, int y) : x(x), y(y) {
        if (y < 0)
            x = -x, y = -y;
        int g = gcd(x, y);
        x /= g;
        y /= g;
    }
};
```

이것이 WolframAlpha나 SageMath와 같은 *컴퓨터 대수 시스템(computer algebra systems)*이 작동하는 방식입니다. 이들은 오로지 심볼릭 표현식만 다루며 값을 실수로 평가하는 것을 피합니다.

이 방법을 사용하면 절대적인 정밀도를 얻을 수 있으며, 유리수만 지원하는 것과 같이 범위가 제한적인 경우 잘 작동합니다. 하지만 이는 큰 계산 비용을 수반합니다. 일반적으로 결과에 이르게 된 연산의 전체 이력을 저장하고 새로운 연산을 수행할 때마다 이를 고려해야 하기 때문입니다. 이력이 늘어남에 따라 이는 빠르게 비현실적인 작업이 됩니다.

### 고정 소수점 수 (Fixed-Point Numbers)

또 다른 접근 방식은 정수를 그대로 사용하되, 특정 상수가 곱해진 것처럼 취급하는 것입니다. 이는 본질적으로 측정 단위를 더 적절한 규모로 바꾸는 것과 같습니다.

일부 값은 정확하게 표현할 수 없으므로 계산이 부정확해질 수 있습니다. 결과를 가장 가까운 표현 가능한 값으로 반올림해야 하기 때문입니다.

이 접근 방식은 최종 금액이 딱 맞아야 하는, 반올림 오차를 관리하는 명확한 방법이 *정말로* 필요한 금융 소프트웨어에서 흔히 사용됩니다. 예를 들어 NASDAQ은 주식 목록에서 기본 단위로 1달러의 1/10000을 사용합니다. 즉, 모든 거래에서 소수점 이하 정확히 4자리의 정밀도를 갖게 됩니다.

```c++
struct money {
    uint v; // 1달러의 1/10000
};

std::string to_string(money) {
    return std::format("${0}.{1:04d}", v / 10000, v % 10000);
}

money operator*(money x, money y) { return {x.v * y.v / 10000}; }
```

반올림 오차를 유발하는 것 외에 더 큰 문제는 스케일링 상수가 적절하지 않을 때 쓸모가 없어진다는 점입니다. 다루는 숫자가 너무 크면 내부 정수 값이 오버플로우되고, 숫자가 너무 작으면 0으로 내림됩니다. 흥미롭게도 전자의 경우 버크셔 해서웨이의 주가가 $\frac{2^{32} - 1}{10000}$ = $429,496.7295에 근접하면서 [NASDAQ에서 문제](https://www.wsj.com/articles/berkshire-hathaways-stock-price-is-too-much-for-computers-11620168548)가 된 적이 있습니다. 32비트 부호 없는 정수에 더 이상 담을 수 없게 된 것이죠.

이러한 문제 때문에 고정 소수점 산술은 아주 작은 숫자와 아주 큰 숫자를 모두 사용해야 하는 분야(예: 특정 물리 방정식 평가)에는 근본적으로 적합하지 않습니다.

$$
E = m c^2
$$

이 방정식에서 $m$은 일반적으로 양성자의 질량($1.67 \cdot 10^{-27}$ kg)과 같은 규모이고 $c$는 빛의 속도($3 \cdot 10^9$ m/s)입니다.

### 부동 소수점 수 (Floating-Point Numbers)

대부분의 수치 계산 애플리케이션에서 우리는 주로 상대 오차에 관심을 가집니다. 계산 결과가 실제 정답과 예를 들어 $0.01\\%$ 이상 차이 나지 않기를 원하며, 그 $0.01\\%$가 절대 단위로 얼마인지는 크게 신경 쓰지 않습니다.

부동 소수점 수는 일정 개수의 유효 숫자(most significant digits)와 숫자의 규모(order of magnitude)를 저장함으로써 이 문제를 해결합니다. 더 정확하게는 정수(가수, *significand* 또는 *mantissa*라고 함)와 고정된 밑(base, 주로 2 또는 10)의 지수(exponent)를 사용하여 표현됩니다. 예를 들면 다음과 같습니다.

$$
1.2345 =
\underbrace{12345}_\text{가수}
\times {\underbrace{10}_\text{밑}\!\!\!\!}
      ^{\overbrace{-4}^\text{지수}}
$$

컴퓨터는 고정된 길이의 이진 워드(binary word)를 다루므로, 하드웨어용 부동 소수점 형식을 설계할 때는 정밀도를 위해 일부 비트를 가수에 할당하고, 범위를 위해 일부 비트를 지수에 할당하는 고정 길이 이진 형식을 원하게 됩니다.

다음은 직접 구현해 본 부동 소수점 수 예시로, 그 개념을 잘 전달해 줄 것입니다.

```cpp
// 직접 만드는 부동 소수점 수
struct fp {
    int m; // 가수 (mantissa)
    int e; // 지수 (exponent)
};
```

이런 방식으로 우리는 $\pm \\; m \times 2^e$ 형태의 숫자를 표현할 수 있습니다. 여기서 $m$과 $e$는 모두 범위가 제한된 *음수일 수도 있는* 정수입니다. 이는 각각 음수나 작은 숫자에 대응합니다. 이러한 숫자들의 분포는 매우 불균일합니다. $[0, 1)$ 범위에 있는 숫자의 개수가 $[1, +\infty)$ 범위에 있는 숫자의 개수와 거의 비슷합니다.

참고로 일부 숫자의 경우 이러한 표현이 유일하지 않습니다. 예를 들어 숫자 $1$은 다음과 같이 표현될 수 있습니다.

$$
1 \times 2^0 = 2 \times 2^{-1} = 256 \times 2^{-8}
$$

가수가 오버플로우되지 않는 선에서 28가지 이상의 다른 방법으로도 표현 가능합니다.

이는 비교나 해싱과 같은 일부 응용 분야에서 문제가 될 수 있습니다. 이를 해결하기 위해 특정 관례를 사용하여 이러한 표현을 *정규화(normalize)*할 수 있습니다. 십진법에서 [표준형(scientific notation)](https://en.wikipedia.org/wiki/Scientific_notation)은 항상 첫 번째 숫자 뒤에 소수점을 찍는 것(`6.022e23`)이며, 이진법에서도 똑같이 할 수 있습니다.

$$
42 = 10101_2 = 1.0101_2 \times 2^5
$$

이 규칙을 따르면 첫 번째 비트는 항상 1이라는 점에 주목하십시오. 이를 명시적으로 저장하는 것은 낭비이므로, 그냥 거기 있다고 가정하고 $[0, 1)$ 범위의 어떤 유리수에 해당하는 나머지 비트들만 저장하겠습니다. 이제 표현 가능한 숫자의 집합은 대략 다음과 같습니다.

$$
\{ \pm \; (1 + m) \cdot 2^e \; | \; m = \frac{x}{2^{32}}, \; x \in [0, 2^{32}) \}
$$

$m$은 이제 0 이상의 값이므로 부호 없는 정수로 만들고, 대신 숫자의 부호를 나타내는 별도의 Boolean 필드를 추가하겠습니다.

```cpp
struct fp {
    bool s;     // 부호: "+"인 경우 "0", "-"인 경우 "1" 
    unsigned m; // 가수 (mantissa)
    int e;      // 지수 (exponent)
};
```

이제 직접 만든 부동 소수점을 사용하여 산술 연산(예: 곱셈)을 구현해 보겠습니다. 새로운 공식을 사용하면 결과는 다음과 같아야 합니다.

$$
\begin{aligned}
c  &= a \cdot b
\\ &= (s_a \cdot (1 + m_a) \cdot 2^{e_a}) \cdot (s_b \cdot (1 + m_b) \cdot 2^{e_b})
\\ &= s_a \cdot s_b \cdot (1 + m_a) \cdot (1 + m_b) \cdot 2^{e_a} \cdot 2^{e_b} 
\\ &= \underbrace{s_a \cdot s_b}_{s_c} \cdot (1 + \underbrace{m_a + m_b + m_a \cdot m_b}_{m_c}) \cdot 2^{\overbrace{e_a + e_b}^{e_c}}
\end{aligned}
$$

계산 과정이 명확해 보이지만 두 가지 미묘한 점이 있습니다.

- 새로운 가수가 이제 $[0, 3)$ 범위에 있게 됩니다. 이것이 1보다 큰지 확인하고 정규화 공식을 적용해야 합니다: $1 + m = (1 + 1) + (m - 1) = (1 + \frac{m - 1}{2}) \cdot 2$.
- 결과 숫자는 정밀도 부족으로 인해 정확하게 표현되지 않을 수 있습니다(매우 높은 확률로). $m_a \cdot m_b$ 항을 고려하려면 두 배 많은 비트가 필요하며, 여기서 우리가 할 수 있는 최선은 이를 가장 가까운 표현 가능한 숫자로 반올림하는 것입니다.

가수 오버플로우 문제를 적절히 처리하기 위해 몇 개의 추가 비트가 필요하므로, $m$에서 한 비트를 예약하여 범위를 $[0, 2^{31})$으로 제한하겠습니다.

```c++
fp operator*(fp a, fp b) {
    fp c;
    c.s = a.s ^ b.s;
    c.e = a.e + b.e;
    
    uint64_t x = a.m, y = b.m; // 더 넓은 타입으로 캐스팅
    uint64_t m = (x << 31) + (y << 31) + x * y; // 62비트 또는 63비트 중간 결과
    if (m & (1<<62)) { // 오버플로우 확인
        m -= (1<<62); // m -= 1;
        m >>= 1;
        c.e++;
    }
    m += (1<<30); // 다음에 내림될 값에 0.5를 더해 "반올림" 수행
    c.m = m >> 31;
    
    return c;
}
```

더 높은 수준의 정밀도가 필요한 많은 응용 분야에서 소프트웨어 부동 소수점 산술을 유사한 방식으로 사용합니다. 하지만 두 실수를 곱할 때마다 이 코드가 컴파일된 10여 개의 명령어 시퀀스를 실행하고 싶지는 않을 것입니다. 따라서 현대적인 CPU에서는 부동 소수점 산술이 하드웨어(보통 그 복잡성 때문에 별도의 보조 프로세서 형태)로 구현되어 있습니다.

x86의 *부동 소수점 연산 장치*(흔히 x87이라 부름)는 별도의 레지스터와 메모리 연산, 기본 산술, 삼각 함수, 그리고 로그, 지수, 제곱근과 같은 일반적인 연산을 지원하는 자체적인 작은 명령어 세트를 가지고 있습니다. 이러한 연산들이 서로 적절히 작동하게 하려면 부동 소수점 표현에 대한 몇 가지 추가적인 세부 사항을 명확히 해야 합니다. 이는 [다음 섹션](../ieee-754)에서 다루겠습니다.
