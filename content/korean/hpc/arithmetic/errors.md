하드웨어 부동 소수점에서 반올림이 작동하는 방식은 매우 단순합니다. 연산 결과가 정확하게 표현 가능하지 않은 경우에만 발생하며, 기본적으로 가장 가까운 표현 가능한 숫자로 반올림됩니다 (두 숫자의 거리가 같은 경우 끝자리가 0인 숫자를 선택합니다).

다음 코드 스니펫을 살펴보십시오.

```c++
float x = 0;
for (int i = 0; i < (1 << 25); i++)
    x++;
printf("%f\n", x);
```

수학적인 결과인 $2^{25} = 33554432$ 대신 $16777216 = 2^{24}$이 출력됩니다. 왜 그럴까요?

부동 소수점 숫자 $x$를 반복적으로 증가시키다 보면, 어느 순간 $(x + 1)$이 다시 $x$로 반올림되는 지점에 도달하게 됩니다. 그러한 첫 번째 숫자는 $2^{24}$ (가수 비트 수 + 1)인데, 그 이유는

$$2^{24} + 1 = 2^{24} \cdot 1.\underbrace{0\ldots0}_{\times 23} 1$$

이 $2^{24}$와 $(2^{24} + 1)$로부터 정확히 같은 거리에 있지만, 위에서 언급한 타이브레이커 규칙에 의해 $2^{24}$로 내림되기 때문입니다. 동시에 그보다 작은 모든 숫자의 증가분은 정확하게 표현될 수 있으므로 애초에 반올림이 발생하지 않습니다.

### 반올림 오차와 연산 순서

부동 소수점 계산 결과는 대수적으로는 올바르더라도 연산 순서에 따라 달라질 수 있습니다.

예를 들어, 덧셈과 곱셈 연산이 순수 수학적 의미에서는 교환 법칙과 결합 법칙이 성립하지만, 반올림 오차는 그렇지 않습니다. 세 개의 부동 소수점 변수 $x$, $y$, $z$가 있을 때, $(x+y+z)$의 결과는 합산 순서에 따라 달라집니다. 동일한 비가환성 원칙이 대부분의(전부는 아닐지라도) 다른 부동 소수점 연산에도 적용됩니다.

컴파일러는 [사양을 준수하지 않는](/hpc/compilation/contracts/) 결과를 생성할 수 없으므로, 이러한 성가신 뉘앙스는 산술 연산에서 피연산자를 재배치하는 일부 잠재적인 최적화를 막게 됩니다. GCC와 Clang에서 `-ffast-math` 플래그를 사용하면 이러한 엄격한 준수를 비활성화할 수 있습니다. 이 플래그를 추가하고 위의 코드 스니펫을 다시 컴파일하면 [상당히 빠르게](/hpc/simd/reduction) 실행되며 우연히 올바른 결과인 33554432를 출력하기도 합니다 (하지만 컴파일러가 덜 정밀한 계산 경로를 선택했을 수도 있음을 인지해야 합니다).

### 반올림 모드 (Rounding Modes)

기본 모드(Banker's rounding이라고도 함) 외에도 4가지 모드를 더 [설정](https://www.cplusplus.com/reference/cfenv/fesetround/)할 수 있습니다.

- 가장 가까운 수로 반올림, 거리가 같은 경우 항상 0에서 멀어지는 쪽으로 반올림 (round to nearest, away from zero)
- 올림 ($+∞$ 방향으로 반올림; 따라서 음수 결과는 0 방향으로 반올림됨)
- 내림 ($-∞$ 방향으로 반올림; 따라서 음수 결과는 0에서 멀어지는 방향으로 반올림됨)
- 0 방향으로 반올림 (이진 결과의 절삭)

예를 들어, 위의 루프를 실행하기 전에 `fesetround(FE_UPWARD)`를 호출하면 $2^{24}$도, $2^{25}$도 아닌 $67108864 = 2^{26}$이 출력됩니다. 이는 $2^{24}$에 도달했을 때 $(x + 1)$이 다음으로 가까운 표현 가능한 숫자인 $(x + 2)$로 반올림되기 시작하여 $2^{25}$에 절반의 시간 만에 도달하고, 그 이후에는 $(x + 1)$이 $(x + 4)$로 올림되어 4배 더 빠르게 진행되기 때문입니다.

대체 반올림 모드의 용도 중 하나는 수치적 불안정성을 진단하는 것입니다. 양의 무한대와 음의 무한대 방향으로 반올림을 전환했을 때 알고리즘의 결과가 실질적으로 달라진다면, 이는 반올림 오차에 취약함을 나타냅니다.

이 테스트는 모든 계산을 낮은 정밀도로 전환하고 결과가 너무 많이 변하는지 확인하는 것보다 나은 경우가 많습니다. 기본인 '가장 가까운 수로 반올림' 정책은 충분한 평균이 주어지면 올바른 "기댓값"으로 수렴하기 때문입니다. 오차의 절반은 올림되고 나머지 절반은 내림되므로, 통계적으로 서로 상쇄됩니다.

### 오차 측정

자연 로그나 제곱근과 같은 복잡한 계산을 수행하는 하드웨어로부터 이러한 보장을 기대하는 것이 놀랍게 보일 수 있지만, 실제로 그렇습니다. 모든 연산에서 가능한 가장 높은 정밀도를 얻는 것이 보장됩니다. 덕분에 잠시 후에 살펴보겠지만 반올림 오차를 분석하기가 매우 쉽습니다.

계산 오차를 측정하는 데는 두 가지 자연스러운 방법이 있습니다.

* 하드웨어나 사양을 준수하는 정확한 소프트웨어를 만드는 엔지니어들은 *ulp (units in the last place)*에 관심을 가집니다. 이는 정확한 실수 값과 실제 계산 결과 사이에 몇 개의 표현 가능한 숫자가 들어갈 수 있는지에 대한 거리입니다.
* 수치 알고리즘을 연구하는 사람들은 *상대 정밀도(relative precision)*에 관심을 가집니다. 이는 근사 오차의 절대값을 실제 정답으로 나눈 값인 $|\frac{v-v'}{v}|$입니다.

어느 경우든, 오차를 분석하는 일반적인 전략은 최악의 경우를 가정하고 단순히 그 범위를 제한하는 것입니다.

단일 기본 산술 연산을 수행하는 경우 발생할 수 있는 최악의 상황은 결과가 가장 가까운 표현 가능한 숫자로 반올림되는 것이며, 이는 오차가 0.5 ulp를 초과하지 않음을 의미합니다. 상대 오차를 같은 방식으로 추론하기 위해, 1과 그 다음 표현 가능한 값 사이의 차이인 *머신 엡실론(machine epsilon)* $\epsilon$을 정의할 수 있습니다 (이는 가수에 할당된 비트 수만큼의 2의 음수 거듭제곱과 같아야 합니다).

즉, 단일 산술 연산 후에 결과 $x$를 얻었다면 실제 값은 다음 범위 어딘가에 있게 됩니다.

$$
[x \cdot (1-\epsilon),\; x \cdot (1 + \epsilon)]
$$

오차의 편재성은 부동 소수점 계산 결과를 바탕으로 이산적인 "예 또는 아니오" 결정을 내릴 때 특히 기억해야 할 중요한 사항입니다. 예를 들어, 같음을 확인하는 방법은 다음과 같아야 합니다.

```c++
const float eps = std::numeric_limits<float>::epsilon; // ~2^(-23)
bool eq(float a, float b) {
    return abs(a - b) <= eps;
}
```

`eps` 값은 애플리케이션에 따라 달라져야 합니다. 위의 값( `float`에 대한 머신 엡실론)은 단 한 번의 부동 소수점 연산에만 적합합니다.

### 구간 산술 (Interval Arithmetic)

어떤 원인이든 오차가 계산 과정 중에 훨씬 커지지 않는 알고리즘을 *수치적으로 안정적(numerically stable)*이라고 합니다. 이는 문제 자체가 *조건이 좋은(well-conditioned)* 경우에만 가능하며, 이는 입력 데이터가 소량 변경될 때 솔루션도 소량만 변경됨을 의미합니다.

수치 알고리즘을 분석할 때 실험 물리학에서 사용하는 것과 동일한 방법을 채택하는 것이 종종 유용합니다. 알 수 없는 실제 값 대신, 해당 값이 존재할 수 있는 구간(interval)을 가지고 작업하는 것입니다.

예를 들어, 변수에 임의의 실수를 연속적으로 곱하는 연산 체인을 생각해 보십시오.

```cpp
float x = 1;
for (int i = 0; i < n; i++)
    x *= a[i];
```

첫 번째 곱셈 후 실제 곱에 대한 $x$의 값은 $(1 + \epsilon)$에 의해 제한되며, 추가 곱셈이 발생할 때마다 이 상한에 다른 $(1 + \epsilon)$이 곱해집니다. 귀납법에 의해 $n$번의 곱셈 후 계산된 값은 $(1 + \epsilon)^n = 1 + n \epsilon + O(\epsilon^2)$과 유사한 하한에 의해 제한됩니다.

이는 상대 오차가 $O(n \epsilon)$임을 의미하며, 보통 $n \ll \frac{1}{\epsilon}$이므로 어느 정도 괜찮습니다.

수치적으로 *불안정한* 계산의 예로 다음 함수를 생각해 보십시오.

$$
f(x, y) = x^2 - y^2
$$

$x > y$라고 가정할 때, 이 함수가 반환할 수 있는 최대값은 대략 다음과 같습니다.

$$
x^2 \cdot (1 + \epsilon) - y^2 \cdot (1 - \epsilon)
$$

이는 다음과 같은 절대 오차에 대응하며

$$
x^2 \cdot (1 + \epsilon) - y^2 \cdot (1 - \epsilon) - (x^2 - y^2) = (x^2 + y^2) \cdot \epsilon
$$

따라서 상대 오차는 다음과 같습니다.

$$
\frac{x^2 + y^2}{x^2 - y^2} \cdot \epsilon
$$

만약 $x$와 $y$의 크기가 비슷하다면 오차는 $O(\epsilon \cdot |x|)$가 될 것입니다.

직접 계산하는 경우 뺄셈이 제곱의 오차를 "확대"합니다. 하지만 이는 대신 다음 공식을 사용하여 해결할 수 있습니다.

$$
f(x, y) = x^2 - y^2 = (x + y) \cdot (x - y)
$$

이 공식에서는 오차가 $\epsilon \cdot |x - y|$로 제한됨을 쉽게 보일 수 있습니다. 또한 원래 공식에 비해 느린 곱셈이 하나 줄고 빠른 덧셈이 하나 늘어난 2개의 덧셈과 1개의 곱셈이 필요하므로 더 빠릅니다.

### 카한 합산 (Kahan Summation)

이전 예제에서 긴 연산 체인은 문제가 되지 않지만, 크기가 다른 숫자를 더하고 빼는 것이 문제임을 알 수 있었습니다. 이러한 문제에 대처하는 일반적인 접근 방식은 큰 숫자는 큰 숫자끼리, 작은 숫자는 작은 숫자끼리 유지하려고 노력하는 것입니다.

표준 합산 알고리즘을 생각해 보십시오.

```c++
float s = 0;
for (int i = 0; i < n; i++)
    s += a[i];
```

곱셈이 아닌 덧셈을 수행하므로 상대 오차는 더 이상 $O(\epsilon \cdot n)$으로 제한되지 않고 입력에 크게 의존합니다.

가장 극단적인 경우로, 첫 번째 값이 $2^{24}$이고 나머지 값들이 $1$인 경우, 합계는 $n$에 관계없이 $2^{24}$가 됩니다. 이는 다음 코드를 실행하여 $16777216 = 2^{24}$가 두 번 출력되는 것을 확인하여 검증할 수 있습니다.

```cpp
const int n = (1<<24);
printf("%d\n", n);

float s = n;
for (int i = 0; i < n; i++)
    s += 1.0;

printf("%f\n", s);
```

이런 현상이 발생하는 이유는 `float`이 23개의 가수 비트만 가지고 있어 $2^{24} + 1$이 정확하게 표현될 수 없고 내림되어야 하는 첫 번째 정수이기 때문입니다. 이는 $s = 2^{24}$에 $1$을 더하려고 할 때마다 발생합니다. 오차는 실제로 $O(n \cdot \epsilon)$이지만, 상대 오차가 아닌 절대 오차 관점에서의 이야기입니다. 위의 예에서 오차는 $2$이며, 마지막 숫자가 $-2^{24}$였다면 오차는 무한대까지 올라갔을 것입니다.

명백한 해결책은 `double`과 같이 더 큰 타입으로 전환하는 것이지만, 이는 그리 확장 가능한 방법이 아닙니다. 우아한 해결책은 더해지지 않은 부분을 별도의 변수에 저장한 다음 다음 변수에 더하는 것입니다.

```c++
float s = 0, c = 0;
for (int i = 0; i < n; i++) {
    float y = a[i] - c; // 첫 번째 반복에서 c는 0입니다.
    float t = s + y;    // s는 크고 y는 작을 수 있어 y의 하위 비트를 잃을 수 있습니다.
    c = (t - s) - y;    // (t - s)는 y의 상위 부분을 상쇄합니다.
    s = t;
}
```

이 트릭은 *카한 합산(Kahan summation)*으로 알려져 있습니다. 상대 오차는 $2 \epsilon + O(n \epsilon^2)$으로 제한됩니다. 첫 번째 항은 맨 마지막 합계에서 발생하며, 두 번째 항은 각 단계에서 엡실론보다 작은 오차로 작업하기 때문입니다.

물론 배열 합산뿐만 아니라 더 일반적으로 적용되는 접근 방식은 `double`과 같이 더 정밀한 데이터 타입으로 전환하여 머신 엡실론을 효과적으로 제곱하는 것입니다. 더 나아가 두 개의 `double` 변수를 하나로 묶어(하나는 값을 저장하고 다른 하나는 표현 불가능한 오차를 저장하여 $a+b$ 값을 나타내도록 함) 확장할 수도 있습니다. 이 접근 방식은 double-double 산술로 알려져 있으며, 유사하게 일반화하여 quad-double 및 더 높은 정밀도의 산술을 정의할 수 있습니다.
