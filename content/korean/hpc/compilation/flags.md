컴파일러에서 높은 성능을 얻기 위한 첫 번째 단계는 성능을 요청하는 것이며, 이는 백 개 이상의 다양한 컴파일러 옵션, 속성(attributes) 및 프라그마(pragmas)를 통해 수행됩니다.

### 최적화 레벨 (Optimization Levels)

GCC에는 속도를 위한 4개 *반*의 주요 최적화 레벨이 있습니다.

- `-O0`는 최적화를 수행하지 않는 기본 레벨입니다 (어떤 의미에서는 컴파일 시간을 위해 최적화한다고 볼 수 있습니다).
- `-O1` (`-O`로도 별칭됨)은 컴파일 시간에 거의 영향을 주지 않으면서 몇 가지 "낮게 매달린 과일(low-hanging fruit)" 최적화를 수행합니다.
- `-O2`는 부정적인 부작용이 거의 없거나 전혀 없다고 알려져 있으며 완료하는 데 합리적인 시간이 걸리는 모든 최적화를 활성화합니다 (대부분의 프로젝트에서 프로덕션 빌드에 사용됩니다).
- `-O3`는 GCC에 구현된 거의 모든 *올바른* 최적화를 활성화하여 매우 공격적인 최적화를 수행합니다.
- `-Ofast`는 `-O3`의 모든 기능에 더해, 엄격한 표준 준수를 깰 수 있지만 대부분의 애플리케이션에 치명적이지 않은 몇 가지 최적화 플래그를 추가로 수행합니다 (예: 부동 소수점 연산이 재배치되어 결과의 가수부(mantissa)가 몇 비트 정도 차이 날 수 있습니다).

`-Ofast`에도 포함되지 않은 다른 최적화 플래그들도 많이 있는데, 이는 매우 상황에 따라 다르며 기본적으로 활성화하면 성능이 향상되기보다 오히려 저하될 가능성이 높기 때문입니다. 이에 대해서는 [다음 섹션](../situational)에서 다룰 것입니다.

### 타겟 지정 (Specifying Targets)

다음으로 할 일은 컴파일러에게 이 코드가 실행될 컴퓨터에 대해 더 많은 정보를 제공하는 것입니다. 지원하는 플랫폼 세트가 작을수록 좋습니다. 기본적으로 컴파일러는 비교적 최신(>2000) x86 CPU라면 어디서든 실행할 수 있는 바이너리를 생성합니다. 이를 좁히는 가장 간단한 방법은 `-march` 플래그를 전달하여 정확한 마이크로아키처를 지정하는 것입니다: `-march=haswell`. 바이너리를 실행할 컴퓨터와 동일한 컴퓨터에서 컴파일하는 경우 자동 감지를 위해 `-march=native`를 사용할 수 있습니다.

명령어 세트는 일반적으로 하위 호환성이 있으므로 지원해야 하는 가장 오래된 마이크로아키처의 이름을 사용하는 것만으로도 충분한 경우가 많습니다. 더 견고한 접근 방식은 CPU가 반드시 가지고 있을 특정 기능을 나열하는 것입니다: `-mavx2`, `-mpopcnt`. 호환되지 않는 CPU에서 충돌을 일으킬 수 있는 명령어를 사용하지 않으면서 특정 머신에 맞춰 프로그램을 *튜닝*하고 싶을 때는 `-mtune` 플래그를 사용할 수 있습니다 (기본적으로 `-march=x`는 `-mtune=x`를 포함합니다).

이러한 옵션들은 컴파일 플래그 대신 프라그마를 사용하여 컴파일 단위별로 지정할 수도 있습니다.

```c++
#pragma GCC optimize("O3")
#pragma GCC target("avx2")
```

이것은 전체 프로젝트의 빌드 시간을 늘리지 않고 단일 고성능 프로시저만 최적화해야 할 때 유용합니다.

### 다중 버전 함수 (Multiversioned Functions)

때로는 단일 라이브러리에 여러 아키처별 구현을 제공하고 싶을 수도 있습니다. 속성 기반 구문을 사용하여 컴파일 타임에 자동으로 다중 버전 함수 중에서 선택할 수 있습니다.

```c++
__attribute__(( target("default") )) // 기본 구현
int popcnt(int x) {
    int s = 0;
    for (int i = 0; i < 32; i++)
        s += (x>>i&1);
    return s;
}

__attribute__(( target("popcnt") )) // popcnt 플래그가 활성화된 경우 사용됨
int popcnt(int x) {
    return __builtin_popcount(x);
}
```

Clang에서는 프라그마를 사용하여 소스 코드에서 타겟 및 최적화 플래그를 설정할 수 없지만, GCC와 동일한 방식으로 속성을 사용할 수 있습니다.
